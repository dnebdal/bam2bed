# bam2bed
## Summary

The bam2bed container works with modified bam files with methylation data generated by the Dorado basecaller from Oxford Nanopore sequencing data.

It has three stages:
- Merge BAM
- Extract methylation BED
- Upload to MNP Flex and download report

## How to run
You need some way to run a Docker/Podman container. 

On Fedora, this will install podman and create the bam2bed container:
```
sudo dnf install podman git
git clone https://github.com/dnebdal/bam2bed
cd bam2bed
podman build -t bam2bed .
```

You should then be able to run the container like this:
```
podman run --rm \
  -v/data/sample1:/work/in:z \
  -v/data/output:/work/out:z \
  bam2bed bed --name sample1
```
This will create `/data/output/sample1` to hold the output files.

The input folder should either directly contain a folder called `bam_passed`, or contain one or more folders that contain `bam_passed` folders.
That is, if you have a layout like this:
```
/data
  + Sample1
       + chip1
           + bam_passed
       + chip2
           + bam_passed
```
You can run with either 
`-v /data/Sample1/:/work/in:z` to use both chip1 and chip2, or
`-v /data/Sample1/chip2:/work/in:z` to only use chip2.

The `:z`suffixes set up the correct SELinux permissions for Fedora, but may not be required on other distros.

## Options
### General
The general syntax is 
`bam2bed merge|bed|mnpflex --name <id> [--tag <tag>] [--threads N] [--only] [--force] [other options]`

The first option is the _verb_, which says where in the merge → bed → mnpflex pipeline to stop.

- `--name`    Sample name to use in the directory and file names
- `--tag`     Additional tag to add to the sample name, e.g. to disambiguate mutliple runs on the same sample with different settings
- `--threads` Threads to use for `samtools merge` and `modkit pileup` (default 8)
- `--only`    Don't run the steps before the given verb. Will fail unless the expected input files exist.
- `--force`   Don't skip a step even if the output file exists.

The `--force` and `--only` settings interact: If you want to do the bedfile extraction again but not the bam merge, 
use `bam2bed bed --force --only`, while specifying only `--force` will do both steps again.

### Merge
`bam2bed merge [general options] [--Nbam N]`

- `--Nbam` How many BAM files to merge. Default 8000.

The subset selected is the first N, after sorting the file path+file name alphabetically.

### BED
Takes no settings at the moment. An option to retain 5hmC information may appear in the future.

### MNP Flex
`bam2bed mnpflex --username <user> --password <password>`

Upload the bed file from the previous stage to [MNP Flex](https://mnp-flex.org), and download the PDF report. This obviously requires a working internet connection.

- `--username`  Your MNP Flex username
- `--password`  Your MNP Flex password

## Example
Merge the first 1000 BAM files and upload to MNP Flex, using 16 threads. 
```
podman run --rm \
  -v/data/sample1:/work/in:z \
  -v/data/output:/work/out:z \
  bam2bed mnpflex --name sample1 --tag 1000bam --Nbam 1000 \
  --threads 16 --username usr1000 --password abcdefghi 
```

This will save its output files in subfolders inside `/data/output/sample1_1000bam/` .
